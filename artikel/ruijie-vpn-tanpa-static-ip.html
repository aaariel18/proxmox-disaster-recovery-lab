RUIJIE / MULTI-SITE

VPN antar-cabang tanpa selalu membayar static IP.

Kita membutuhkan endpoint VPN yang bisa ditemukan. Itu tidak selalu berarti setiap cabang harus memiliki alamat IP publik yang tetap.

Pertanyaan yang tepat sebelum membeli perangkat

Untuk jaringan multi-site, biaya berulang perlu dilihat bersama jumlah lokasi dan durasi pemakaian. Artikel GitHub saya membahas alternatif yang layak diuji: memakai koneksi existing, dynamic public IP, gateway Ruijie/Reyee, dan DDNS.

Batasan yang tidak boleh dilewatkan

DDNS hanya memperbarui pemetaan hostname ke alamat IP. DDNS tidak mengubah alamat private atau CGNAT menjadi public IP yang dapat dijangkau dari Internet. Ini adalah rancangan dan bahan PoC, bukan jaminan kompatibilitas untuk semua ISP atau perangkat.

Opsi A: hostname Ruijie/Reyee DDNS

Pendekatan ini memanfaatkan hostname DDNS dalam ekosistem Ruijie/Reyee. Gateway memperbarui pemetaan ketika public IP berubah, sementara peer VPN menggunakan hostname tersebut.

Dynamic public IP
        |
Ruijie / Reyee gateway
        |
Ruijie DDNS hostname
        |
IPsec / Easy VPN antar-site

Opsi ini cocok sebagai titik awal PoC ketika perangkat, firmware, dan fitur yang digunakan mendukungnya. Verifikasi dukungan model, mode VPN, dan batasan fitur pada dokumentasi perangkat yang benar-benar dipakai.

Opsi B: domain perusahaan dan cPanel Dynamic DNS

Hostname milik perusahaan membuat penamaan endpoint lebih konsisten. Misalnya vpn-hq.example.com untuk kantor pusat dan vpn-warehouse.example.com untuk gudang. Nama tersebut hanya contoh, bukan konfigurasi aktif.

cPanel Dynamic DNS menyediakan webcall URL untuk memperbarui alamat IP hostname. Jalankan pembaruan dari jaringan yang alamat publiknya hendak didaftarkan, menggunakan host yang disetujui. Simpan URL tersebut sebagai rahasia: jangan masukkan ke repositori publik, screenshot, atau log terbuka.

HQ dynamic public IP
        |
Local updater / webcall
        |
cPanel Dynamic DNS
        |
vpn-hq.example.com
        |
Branch IPsec peer

Periksa bahwa zona DNS authoritative memang mendukung pembaruan melalui cPanel yang dipakai. Jika DNS dikelola di tempat lain, pembaruan di cPanel saja belum tentu mengubah record publik.

Dynamic public IP berbeda dari CGNAT

Bandingkan alamat WAN router dengan alamat publik yang terlihat dari Internet. Alamat RFC1918 atau rentang shared address 100.64.0.0/10 perlu diperiksa lebih lanjut. Konfirmasikan reachability dan kebijakan ISP, bukan hanya nama paket Internet.

Pada contoh IPsec di dokumentasi Reyee, peer gateway dapat berupa IP publik atau domain. Jika endpoint berada di belakang NAT yang dapat dikendalikan, kebutuhan pemetaan UDP 500/4500 harus diperiksa sesuai topologi. Jangan membuka akses manajemen router ke Internet sebagai pengganti konfigurasi VPN yang benar.

VPN terhubung bukan berarti semua akses diizinkan

Pakai subnet unik per site dan hindari overlapping subnet. Pisahkan kebutuhan POS, staff, CCTV, guest Wi-Fi, dan management melalui segmentasi yang sesuai.

POS        -> application server   : sesuai kebutuhan
CCTV       -> monitoring server    : sesuai kebutuhan
Guest      -> internal network    : deny
Management -> network devices     : akses terbatas

Aturan di atas adalah contoh kebijakan, bukan konfigurasi siap diterapkan tanpa pemeriksaan. Batasi traffic VPN ke layanan yang benar-benar diperlukan dan dokumentasikan perubahan.

PoC: satu HQ dan dua cabang

  1. Uji perubahan public IP dan waktu pembaruan DNS.
  2. Periksa apakah tunnel pulih dan aplikasi kembali dapat diakses.
  3. Uji akses POS, aplikasi internal, dan pembatasan antar-segmen.
  4. Periksa kebutuhan bandwidth dan latency CCTV.
  5. Uji failover ISP jika dual WAN digunakan.
  6. Pastikan remote troubleshooting tetap bisa dilakukan secara aman.

Catat waktu dan hasil pengujian nyata. Perilaku re-resolution DNS, TTL, firmware, dan recovery tunnel perlu diuji pada kombinasi perangkat yang akan dibeli.

Bandingkan biaya dengan data aktual

Biaya static IP per tahun
= jumlah site x biaya bulanan per site x 12

Bandingkan dengan investasi gateway, layanan DDNS/domain, pemeliharaan, dan biaya operasional alternatifnya. Tidak ada angka penghematan yang diklaim di sini karena tarif ISP dan kebutuhan setiap site berbeda.

Hostname yang konsisten dapat membantu. Reachability dan kontrol akses tetap harus dibuktikan.
